# Обращение в Hoster.KZ по запуску Node.js на omoikiri.kz

Дата: 21 октября 2026 г.
Заявка: №2709962
Домен: `omoikiri.kz`
Рабочий поддомен: `staging.omoikiri.kz`

Здравствуйте!

Проверили предложенную вами конфигурацию. В Plesk для основного домена задали корневую папку сайта `/production-proxy/public`, расположенную внутри корневой папки Node.js-приложения `/production-proxy`. Файл запуска приложения — `app.js`. Предупреждение Plesk о несовместимости этих путей исчезло. После нажатия «Включить Node.js» интерфейс сообщил, что Node.js включён.

Однако запросы к основному домену не попали в приложение:

| Проверка | Результат |
| --- | --- |
| `https://omoikiri.kz/` | HTTP 403 |
| `https://omoikiri.kz/healthz` | HTTP 404 |
| `https://staging.omoikiri.kz/healthz` | HTTP 200 |

В журнале Apache для основного домена зафиксировано:

```text
AH01276: Cannot serve directory /var/www/vhosts/omoikiri.kz/production-proxy/public/: No matching DirectoryIndex (index.html,index.cgi,index.pl,index.php,index.xhtml,index.htm,index.shtml,index.php,index.html) found, and server-generated directory index forbidden by Options directive
```

Похоже, Apache обрабатывал корневую папку как обычный статический сайт, а маршруты не передавались Node.js/Passenger. После проверки мы сразу вернули корневую папку `/httpdocs`, отключили Node.js для `omoikiri.kz` и подтвердили восстановление временной переадресации HTTP 302 на работающий staging. Файлы старого сайта и база данных не изменялись.

Просим техническую поддержку:

1. Проверить сгенерированную конфигурацию Apache/nginx и Passenger для `omoikiri.kz` после включения Node.js: почему при корректном расположении document root запросы не доходят до `app.js`.
2. Проверить, поддерживается ли одновременно Node.js на `omoikiri.kz` и `staging.omoikiri.kz` в этой подписке, и не сбрасывается ли настройка Node.js при сохранении параметров хостинга.
3. Сообщить точные параметры Plesk или выполнить исправление конфигурации сервера, чтобы основной домен обслуживал Node.js-приложение, без смены DNS и без влияния на staging.
4. Прислать точную запись упомянутой вами JavaScript-ошибки на staging: дату и время, путь к файлу или URL и полный текст ошибки. Без этих данных мы не можем её воспроизвести.

Пожалуйста, не меняйте текущую переадресацию основного домена и не переключайте публичный трафик без согласования: сейчас она сохраняет доступность каталога и заказов. Мы готовы повторить проверку после вашего ответа и сразу проверить главную, `/healthz`, карточку товара и оформление заказа на основном адресе.
